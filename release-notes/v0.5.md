Win-Preview v0.5 is a reliability release: it fixes several cases where an action could land on the wrong document, leave a document half-changed, or lose what you had just typed.

## Download

**Win-Preview-v0.5-win-x64.zip** is for Windows 10 (1809+) and Windows 11, x64. Unzip it anywhere and run `WinPreview.exe`. Nothing needs to be installed; .NET and the Windows App SDK are included. To update from an earlier version, unzip into a new folder (unzipping over the old one would leave behind files this version no longer uses).

> The app isn't code-signed yet, so Windows SmartScreen may warn on first launch. Choose **More info → Run anyway**. The SHA-256 checksum is in `Win-Preview-v0.5-win-x64.zip.sha256`.

## Fixed in v0.5

**Remove Background**
- If you switched to another tab while the background was being removed, the result could be applied to the image in that tab. It now always goes to the image you started on.
- If that image is edited (for example cropped) before the removal finishes, the result is no longer applied to the changed picture; you're asked to try again.
- Starting a second removal while one is running now says so instead of doing nothing.

**Closing a window**
- Clicking the close button a second time while "Do you want to save changes?" was showing, or with another dialog open, showed a "Something went wrong" message. Extra clicks are now ignored.

**Editing pages**
- If rotating, deleting, reordering, inserting or cropping pages failed part-way, the document could be left partly changed with nothing to undo. It is now put back exactly as it was.

**Typing and forms**
- Text you're typing in a text box or a PDF form field is now saved before rotating, deleting, cropping or inserting pages, and before Save As, Export, Share, Slideshow, Undo and Redo.
- After selecting a markup (for example from the Highlights & Notes list) while a form field had the cursor, Delete and the arrow keys now act on the markup instead of the field.

**Drawing**
- A shape now keeps the kind you started drawing (rectangle, oval, line or arrow) even if the tool changes during the drag.
- If the drag is interrupted (for example by switching windows), the shape ends where the pointer was, not as a default-size shape where you started.
- If pages change while you're dragging (for example undoing a rotation), the drag is now dropped instead of being applied to the rebuilt pages, where it could clear the Redo history.

**Live Text**
- On images, the text cursor appears as soon as text recognition finishes, without having to move the mouse.
