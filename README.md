# Win-Preview

A free Windows app for viewing and marking up PDFs and images, inspired by macOS Preview.
Built with C#, WinUI 3 (Windows App SDK) and PDFium.

Win-Preview is an independent project, not affiliated with or endorsed by Apple Inc.

This is a clean-room implementation. Features are built from Apple's public
[Preview User Guide](https://support.apple.com/guide/preview/welcome/mac) and observed behavior.
No Apple code, binaries or artwork are used, and none were decompiled.

## Install

1. Download the latest `Win-Preview-…-win-x64.zip` from the
   [Releases page](https://github.com/titleunknown/win-preview/releases/latest).
2. Unzip it anywhere, for example `C:\Users\<you>\Apps\Win-Preview`.
3. Run `WinPreview.exe`. To open files with it, drag them onto the window, use **Open With → Choose another app**,
   or pin it to Start or the taskbar.

It runs on Windows 10 (1809 or later) and Windows 11, x64. Nothing else needs to be installed: the .NET runtime
and Windows App SDK are included. To uninstall, delete the folder.

The app isn't code-signed yet, so Windows SmartScreen may show "Windows protected your PC" the first time.
Choose **More info → Run anyway**. Each release lists a SHA-256 checksum you can verify with
`Get-FileHash Win-Preview-*.zip`. Signing through SignPath Foundation is being set up; see
[docs/CODE_SIGNING.md](docs/CODE_SIGNING.md).

## Building from source

### Requirements

- Windows 10 1809 or later (Windows 11 recommended)
- [.NET 10 SDK](https://dotnet.microsoft.com/download): `winget install Microsoft.DotNet.SDK.10`

You don't need Visual Studio. Everything builds with the `dotnet` CLI.

### Build, test, run

```bash
dotnet build src/WinPreview.App -p:Platform=x64
dotnet test tests/WinPreview.Core.Tests
src/WinPreview.App/bin/x64/Debug/net10.0-windows10.0.22621.0/win-x64/WinPreview.exe path/to/file.pdf
```

The app is unpackaged and bundles the Windows App SDK runtime, so the build output folder runs as-is.

To get sample files, run `dotnet run --project tools/SampleGen -- samples`. It writes `samples/sample.pdf` (text
pages plus a fillable form) and `samples/photo.png`.

For diagnostics, set `WINPREVIEW_LOG=1` and the app appends to `%TEMP%\winpreview.log`.

## Layout

| Path | What it is |
|---|---|
| `src/WinPreview.Core` | UI-free engine: PDFium P/Invoke (`Pdf/`), markup model, hit-testing, rasterizing, signatures. Unit-tested. |
| `src/WinPreview.App` | WinUI 3 app: `Session/` (open document, undo, save/export, image codecs), `Views/` (document surface, page rendering, input), `MainWindow*` (toolbar, sidebar, commands). |
| `src/WinPreview.Resources` | A resource-only DLL holding the custom mouse cursors (magnifier, hands). `Cursors.res` is generated by `tools/CursorGen`. |
| `tests/WinPreview.Core.Tests` | xUnit tests run against real PDFium. They check round-trips, rendering, forms and page operations. |
| `tools/CursorGen` | Draws the cursors and writes `Cursors.res`: `dotnet run --project tools/CursorGen -- src/WinPreview.Resources/Cursors.res`. |
| `tools/SampleGen` | Generates sample documents. `SampleGen render <pdf> <page> <png>` renders a page the way any other viewer would. |

## How markups work

- On open, every annotation the tools can edit is read into a `MarkupItem` and removed from the in-memory PDF.
  The app then draws it as an editable XAML overlay.
- On save, markups are written back as real PDF annotations with appearance streams, so Acrobat, Edge and
  Chrome show them identically:
  - highlight, underline, strikeout
  - ink
  - rectangle and oval
  - note
  - lines, arrows and text boxes, which are written as stamps
- Annotations the app can't represent are left untouched.
- Image markups are flattened into the pixels on save, using the same PDFium renderer. A markup therefore looks
  the same in a PNG as in a PDF.

See [FEATURES.md](FEATURES.md) for parity status against Preview.

## Privacy

Win-Preview does not collect, store or send any information about you or your documents, and it contains no
analytics or telemetry. Everything, including text recognition, background removal and PDF compression, runs on
your PC.

The program doesn't transfer information to other networked systems unless you specifically ask it to. The only
network access is the optional **high-quality background-removal model**: if you choose it, the app asks first and
then downloads one file (about 179 MB) from GitHub. Nothing about you or your files is sent with that request.
Saved signatures (`%LOCALAPPDATA%\WinPreview`) and the downloaded model (`%LOCALAPPDATA%\Win-Preview`) stay on
your PC.

Passwords you enter are kept in memory only. To encrypt a PDF, the app passes the password to the bundled qpdf tool
through a short-lived temporary file (not the command line, so other programs can't see it in the process list),
which is deleted as soon as qpdf finishes.
